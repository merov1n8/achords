# ADR-0054: Local apps opened and closed by achords

Status: Accepted (2026-11-21)

- Context: The Blender and Unity integrations (ADR-0034) talk to an app on this Mac: the Blender add-on's socket, the MCP for Unity bridge in the Unity Editor. When the app is closed the integration is useless, so agents opened it themselves through a shell command (`open -a …`). A shell rules out every integration with credentials on the same agent (ADR-0034: no shell next to secrets), e.g. Meshy next to Blender. Owner decision (2026-11-21): achords opens and closes these apps itself, without asking per open.

- Decision:
  - **Catalog field `app`.** An entry may name the app it needs: `name` (also the AppleScript name for quitting), `open` (the arguments of macOS `open`, fixed in the catalog and required to contain `-g` so the app starts in the background), optional `process` (exact process name for the running check, default `name`), `requires` (a file the working folder must contain, relative), and `ready: {port, timeout_s}` (ready once something listens on `127.0.0.1:<port>`; `timeout_s` 1–300, default 90). `{workdir}` in an `open` argument is the run's working folder, the same value as `{workdir}` in env literals: the agent's first own folder (`fs.write`, then `fs.read`), or the client project's files folder. Nothing in the arguments comes from the agent or the task. Names match `[A-Za-z0-9 ._-]` and are passed as arguments only, never spliced into a shell or AppleScript source.
  - **Unity project.** The Unity entry opens `-a Unity --args -projectPath {workdir}` and `requires: ProjectSettings/ProjectVersion.txt`: the agent's working folder is the project (as for game-dev today). If it is not a Unity project, nothing is opened and the integration is left out of the run with that reason. An owner with several Editor versions installed copies the entry to `~/.achords/catalog/unity.yaml` with the full path of the right `Unity.app`.
  - **Open.** While a run is prepared, for every granted integration with `app` (not for container runs: the VM cannot reach apps on this Mac, ADR-0051): if a process with that exact name runs (`pgrep -x`), nothing happens, whoever opened it. Otherwise the gateway runs `open` and waits until the process appears and, with `ready`, the port answers (polling every second, bounded by `timeout_s`, default 60 s without `ready`). Failure (the app is not installed, `open` fails, no answer in time) leaves that integration out of the run with one plain line ("Not available in this run: Blender (could not be opened)"); the work goes on. An open adds one line to the agent's prompt so it can say so in its report. Ready checks happen only when achords opened the app; an app that was already running is used as is.
  - **Close.** The gateway remembers the apps it opened, with their pid (in memory). Every 10 seconds it asks which apps active tasks need: tasks queued, running or waiting (delegated or asked the owner), not parked, whose agent's manifest lists an integration with that app. This covers every chain, so an app is never closed under another workflow. An app it opened that no active task has needed for 3 minutes (grace period, so the next step of a workflow does not reopen it) is quit gracefully (`osascript`: `tell application <name> to quit`). If the app's pid changed (the owner quit and reopened it) or it is gone, it is no longer achords' and is left alone. An app the owner opened is never closed.
  - **Log.** Every open, readiness, failure and close is written to the gateway log (`apps: …`).
  - **Platform.** `macApps()` in `@achords/platform` (pgrep, open, osascript, a TCP check) behind an injectable `AppControl`; the gateway uses it on macOS only.

- Consequences: Agents that use Blender or Unity need no shell for it, so they can also hold keyed integrations such as Meshy. The Blender add-on still has to be installed and enabled once (its socket starts with Blender). A first Unity start with a large import can exceed the wait; that run goes on without Unity and the next one finds it running. Quitting asks the app as the Quit menu does: with unsaved changes it may stay open with its save dialog; achords does not retry. The record of opened apps does not survive a gateway restart, so an app opened before a restart stays open (never closed by mistake). The web connection test does not open apps. Unity's bridge picks another port when 6400 is taken; the ready check then waits for 6400 in vain and the run goes on without Unity.
