# ADR-0053: Skill folders and agent scopes

Status: Accepted (2026-11-21)

- Context: ADR-0049 stores one Markdown file per skill per workspace. The owner also installs third-party Agent Skills packs locally: a folder per skill with `SKILL.md` and `scripts/`, `references/`, `assets/` beside it, nested in category folders (e.g. `skills/agents/advertiser/claude-ads/skills/ads-google/SKILL.md`), often hundreds of skills, some meant for one agent only. Agents must find them, read the files beside a `SKILL.md` and run bundled scripts, without anything new being writable and without the repository shipping any skill content.

- Decision:
  - Scopes under `$ACHORDS_HOME/skills/`: `shared/`, `<workspace>/` (as before) and `agents/<agent-id>/`, seen only by that agent. A run sees its agent scope, its workspace and shared; on a name clash the agent scope wins, then the workspace, then shared. A switched-off skill does not hide a weaker one of the same name. `agents` is reserved and no longer a valid skill workspace name.
  - Discovery inside a scope, breadth first (shallowest first), entries in name order: every `SKILL.md` at any depth is a folder skill (name from its frontmatter, else its folder; description from frontmatter; `enabled` default true). A `.md` elsewhere is a single-file skill when its frontmatter has `name` and `description`; a `<slug>.md` at the scope's top is one regardless and keeps ADR-0049's rule that the file name is the name. Markdown inside a skill folder (at any depth) belongs to that skill and is never a skill of its own; Markdown without that frontmatter is not a skill. Hidden folders and `node_modules` are skipped, symlinked folders inside a scope are not followed. Limits per scope: 8 folders deep and 2000 directory entries; beyond them the rest is left out with a warning. Names must be unique within a scope: the first (shallowest) wins, the gateway log warns once per message. Names found on disk may use letters, digits, `_`, `.` and `-` (≤ 64); others are left out with a warning.
  - Index: one line per visible enabled skill, `- <name>: <description> (<absolute path of SKILL.md or the .md>)`, descriptions cut at 200 characters, with the note to read the file with Read or `skill_read` before using it and that files beside a `SKILL.md` belong to the skill. `skill_read(name)` returns the body; for a folder skill also its folder and up to 50 file paths relative to it (hidden folders skipped, "… and N more").
  - Read access: the existing scope folders a run sees are added to its read roots (Read/Glob/Grep allow rules and `--add-dir`, so the codex sandbox follows the same rules) and, for container runs (ADR-0051), shared read-only. Never write rules. Bundled scripts run only through the agent's own `shell.allow` commands.
  - Writing stays ADR-0049's: owner add/edit and approved proposals write single files (`<scope>/<name>.md`, or where that single-file skill already is). The owner may also target `agents/<id>` (the agent must exist); agent proposals stay in their workspace, or patch an existing single-file skill of their agent scope. Folder skills are never written by achords except `enabled`: the web switch sets `enabled: false|true` in the `SKILL.md` frontmatter and keeps every other byte; a proposal that would replace a folder skill is refused, Edit and Delete refuse it too (the owner changes it in its folder).
  - Web: the Skills page groups by scope (Shared, workspaces, Agent: `<id>`), collapsible (collapsed from 20 skills on), with a search over name and description; folder skills have the switch and a read-only view (`GET /api/skills/<scope>/<name>`: body and file list). The list omits folder skills' bodies. Routes accept `agents/<id>` as the scope.

- Consequences: Installed packs work without conversion and stay owner-maintained in their folders. The index grows with every installed skill (about 250–300 characters per line with long descriptions and paths: 250 skills add 250 lines, roughly 15–19k tokens per run); the owner keeps that down by switching skills off or scoping packs to the agent that needs them. Discovery re-reads the visible scopes at each run start and page poll; at a few hundred skills that is a few milliseconds of file reads. Skill text from third-party packs is owner-installed, so like other skills it carries no untrusted mark; the owner is responsible for what they install. Not covered: editing folder skills in the web, deleting them, and symlinked folders inside a scope.
